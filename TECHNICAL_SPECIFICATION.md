# Техническое задание для React Native-разработчика

**Экраны «Клиент» и «Профиль сотрудника»**

| | |
|---|---|
| **Время** | 4–6 часов |
| **Сдача** | GitHub + README |
| **Стек** | React Native, TypeScript, monorepo |
| **Данные** | React Query + mock |

## 1. Задача

Реализовать мини-приложение из двух экранов по макету ниже.
Экраны должны быть визуально и структурно близки к корпоративному CRM-приложению:
карточки, секции, key-value строки, интерактивные ссылки, кнопки действий.

## 2. Стек и архитектура

**Технологии:** React Native · TypeScript · monorepo · React Query · React Navigation

Проект оформляется как monorepo. Данные получаются через React Query —
реальные HTTP-запросы делать не нужно, но структура должна быть как в production:
отдельный API-слой, hooks с `useQuery`, query keys, loading/error states.
Функции API возвращают данные из mock-файлов (с небольшой задержкой через `setTimeout` — по желанию).

## 3. Экраны

### 3.1. Экран «Клиент» 

Экран детальной карточки клиента по макету (рис. 1, левый экран).

**Требования:**

- сделать как отдельный микро-фронт который подключается к host
- шапка с аватаром (буква или изображение), названием компании, статусом и ИНН;
- секция «Основная информация» — отрасль, сегмент, менеджер, телефон;
- секция «Контакты» — список контактных лиц компании с фото, должностью и телефоном;
- телефон и email — интерактивные (`Pressable` + `Linking`);
- тап по менеджеру («И. Петров») открывает экран «Профиль сотрудника»;
- кнопка «Создать активность» — Toast или Alert (форму создавать не нужно).

### 3.2. Экран «Профиль сотрудника»

Экран по макету (рис. 1, правый экран). Открывается из карточки клиента по тапу на менеджера.

**Требования:**

- сделать как отдельный микро-фронт который подключается к host
- шапка с фото/аватаром, ФИО и должностью;
- секция «Основная информация» — должность, рабочий телефон, почта, подразделение;
- секция «Часовой пояс» — timezone и текущее время, обновляемое минимум раз в минуту;
- кнопка «Изменить» — по желанию (Alert или Picker с выбором timezone).

## 4. Данные и API-слой

Mock-данные лежат в JSON-файлах или TypeScript-константах. API-функции имитируют сетевые вызовы.
